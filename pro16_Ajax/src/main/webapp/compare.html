fetch 와 jQuery 문법 대조표

같은 화면을 두 방식으로 만들어 두었습니다. 왼쪽은 fetch(step1~3), 오른쪽은 jQuery(jq1~3) 입니다. 두 파일을 나란히 열어 놓고 이 표와 함께 보면 차이가 한눈에 들어옵니다.

3. 1단계 코드 나란히 보기

fetch (step1.html)

async function 날씨조회(){
  const 결과영역 =
    document.getElementById("result");

  try {
    const res = await fetch(주소);

    if(!res.ok)
      throw new Error(res.status);

    const data = await res.json();

    결과영역.innerHTML = 만든HTML;

  } catch (err) {
    결과영역.innerHTML = "실패";
    console.error(err);
  } finally {
    버튼.disabled = false;
  }
}

jQuery (jq1.html)

function 날씨조회(){
  const 결과영역 = $("#result");

  $.ajax({
    url  : 주소,
    type : "get",
    data : { latitude : 위도 },
    dataType : "json",

    success : function(response){
      결과영역.html(만든HTML);
    },

    error : function(xhttp){
      결과영역.html("실패");
    },

    complete : function(){
      버튼.prop("disabled", false);
    }
  });
}
1단계에서는 차이가 작습니다. jQuery 가 조금 더 짧고 상태 검사도 자동입니다. 여기까지만 보면 jQuery 가 편해 보입니다.

4. 2단계 코드 나란히 보기 (차이가 벌어지는 지점)

fetch (step2.html) - 위에서 아래로

try {
  const 지오응답 = await fetch(지오주소);
  const 지오데이터 = await 지오응답.json();
  const 장소 = 지오데이터.results[0];

  const 날씨응답 = await fetch(날씨주소);
  const 날씨데이터 = await 날씨응답.json();

  화면에 표시;

} catch (err) {
  오류 안내;       모든 오류를 한 곳에서
} finally {
  버튼 복구;       뒷정리도 한 곳에서
}

jQuery (jq2.html) - 안쪽으로 파고듦

$.ajax({
  success : function(지오데이터){

    const 장소 = 지오데이터.results[0];

    $.ajax({
      success : function(날씨데이터){

        화면에 표시;

      },
      error : function(){ 오류 안내; },
      complete : function(){ 버튼 복구; }
    });

  },
  error : function(){ 오류 안내; }
});
여기가 핵심입니다.
jQuery 는 $.ajax 안에 $.ajax 가 들어갑니다. 요청이 세 번이면 세 단계, 네 번이면 네 단계까지 안쪽으로 파고듭니다. 이런 모양을 실무에서 콜백 지옥이라고 부릅니다.

게다가 오류 처리와 버튼 복구 코드가 여러 곳에 흩어집니다. fetch 는 catch 하나, finally 하나면 끝납니다.

이것이 실무가 fetch 로 옮겨 간 가장 큰 이유입니다.

5. 3단계 동시 호출 나란히 보기

fetch (step3.html)

const [날씨응답, 대기응답] =
  await Promise.all([
    fetch(날씨주소),
    fetch(대기주소)
  ]);

const [날씨데이터, 대기데이터] =
  await Promise.all([
    날씨응답.json(),
    대기응답.json()
  ]);

날씨데이터.current 로 바로 사용

jQuery (jq3.html)

const 날씨요청 = $.ajax({ ..... });
const 대기요청 = $.ajax({ ..... });

$.when(날씨요청, 대기요청)
 .done(function(날씨결과, 대기결과){

   const 날씨데이터 = 날씨결과[0];
   const 대기데이터 = 대기결과[0];
                          이 [0] 이 함정
   화면에 표시;
 })
 .fail(function(){ 오류 안내; })
 .always(function(){ 버튼 복구; });
jQuery 에서 가장 많이 틀리는 부분
$.when 의 결과는 데이터가 곧바로 오지 않고 배열로 감싸져서 옵니다.

날씨결과 = [ 실제데이터, "success", xhr객체 ]

그래서 날씨결과[0] 처럼 [0] 을 반드시 붙여야 합니다. 빠뜨리면 undefined 가 나옵니다.

6. 언제 무엇을 쓰는가

상황선택이유
기존 JSP 프로젝트 유지보수jQuery이미 그 문법으로 짜여 있어 읽고 고칠 줄 알아야 합니다
새 프로젝트 시작fetch불러올 파일이 없고 요청이 늘어나도 코드가 단순합니다
요청 한 번만 보낼 때둘 다 무방차이가 거의 없습니다
요청을 여러 번 이어서fetch콜백 중첩이 없어 읽기 쉽습니다
화면 효과가 많은 페이지jQuery애니메이션과 선택자 기능이 함께 들어 있습니다
결론
둘 중 하나만 알면 됩니다가 아니라, 둘 다 읽을 줄 알아야 합니다. 취업 후 첫 업무는 대부분 기존 코드 수정이고 그 코드는 jQuery 입니다. 새로 만드는 부분은 fetch 로 짜면 됩니다.
