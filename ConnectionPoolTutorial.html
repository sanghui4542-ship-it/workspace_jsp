커넥션풀(Connection Pool)
미리 만들고, 빌려 쓰고, 반납한다

매 요청마다 DB에 새로 접속하던 방식을 버리고, 톰캣이 미리 만들어 둔 연결을 꺼내 쓰는 과정을 5단계 애니메이션으로 직접 눌러 보며 배웁니다.

STEP 1

왜 커넥션풀이 필요한가?

💡 문제 상황 — 지금까지의 DAO는 요청이 올 때마다 DriverManager.getConnection()으로 DB 접속을 새로 생성하고, 끝나면 완전히 끊었습니다. 접속 생성은 시간이 오래 걸리는 작업이라, 사용자가 많아질수록 서버가 느려집니다.

아래 버튼을 눌러 기존 방식과 커넥션풀 방식이 요청 3건을 처리하는 속도를 비교해 보세요.

[ 요청 3건 처리 속도 비교 · 막대가 끝까지 차면 응답 완료 ]

📌 결론 한 줄 — "생성은 한 번, 사용은 여러 번!" DB 연결을 미리 여러 개 만들어 보관해 두고, 필요할 때 빌려 쓰고 돌려주는 방식이 커넥션풀(Connection Pool)입니다.

STEP 3

JNDI — 이름(key)으로 풀을 꺼내 쓰는 기술

JNDI(Java Naming and Directory Interface)는 자원을 키(Key)와 값(Value)으로 저장해 두고, 나중에 키로 꺼내 쓰는 기술입니다. 열쇠(key)로 사물함(value)을 여는 방식과 같습니다.

이미 배운 것들 중에도 "키로 값을 꺼내는" 구조가 있었습니다.

이미 배운 예키(key)값(value)
getParameter("name")input의 name 속성사용자가 입력한 값
HashMap.get("key")put으로 저장한 키put으로 저장한 값
DNS (도메인 → IP)naver.comIP 주소

아래 버튼을 눌러 DAO가 JNDI 저장소에서 커넥션풀을 꺼내는 순간을 확인해 보세요.

[ DAO 코드 1줄이 실행되는 순간 ]
dataFactory = (DataSource) envContext.lookup("jdbc/oracle");

MemberDAO (웹 애플리케이션)

키 "jdbc/oracle" 로
lookup(조회)을 요청합니다.

→

톰캣의 JNDI 저장소 (key / value 모음)

"jdbc/oracle"커넥션풀 객체(DataSource)
"mail/smtp"메일서버 객체 (예시)
💡 왜 이렇게 할까? — 톰캣이 커넥션풀을 미리 만들어 "jdbc/oracle"이라는 이름(key)으로 등록해 둡니다. 그러면 DAO는 URL·아이디·비밀번호를 코드에 직접 쓰지 않고 이름만 알면 DB에 연결할 수 있습니다. → 보안 + 유지보수가 좋아집니다. (DB 비밀번호가 바뀌어도 자바 코드는 수정할 필요가 없습니다.)
STEP 4

톰캣에 커넥션풀 설정하기 (4단계)

[다음 단계]를 눌러 설정 순서를 하나씩 밝혀 보세요.

[ 톰캣의 ConnectionPool 설정 과정 ]
1
JDBC 드라이버 설치
ojdbc6.jar 파일을 프로젝트의 WebContent/WEB-INF/lib 폴더에 넣습니다.
DB와 대화할 통역 프로그램을 먼저 준비하는 단계입니다.
2
커넥션풀 라이브러리 설치
tomcat-dbcp-7.0.30.jar 파일을 같은 WEB-INF/lib 폴더에 넣습니다.
풀을 만들고 관리하는 기능이 이 jar 안에 들어 있습니다. (DBCP = DataBase Connection Pool)
3
context.xml에 <Resource> 설정
이클립스의 Servers > context.xml 파일에 연결할 DB 정보를 JNDI 이름으로 등록합니다. (아래 코드 참고)
4
DAO에서 JNDI 이름으로 연결
MemberDAO에서 lookup("jdbc/oracle")로 풀을 받아 dataFactory.getConnection()으로 연결을 빌립니다. (STEP 5에서 코드 확인)

3단계에서 작성하는 context.xml

<Resource
    name="jdbc/oracle"                              ← JNDI 이름(key). DAO가 이 이름으로 꺼냄
    auth="Container"                               ← 인증 주체 = 톰캣(컨테이너)
    type="javax.sql.DataSource"                    ← 저장되는 값의 종류 = 커넥션풀 객체
    driverClassName="oracle.jdbc.driver.OracleDriver" ← DB 종류별 드라이버 클래스
    url="jdbc:oracle:thin:@localhost:1521:XE"       ← 접속 주소·포트·SID
    username="scott"                              ← DB 접속 아이디
    password="tiger"                              ← DB 접속 비밀번호
    maxActive="50"                                ← 동시에 빌려줄 수 있는 최대 연결 수
    maxWait="-1"                                  ← 빈 연결이 생길 때까지 기다리는 최대 시간(-1=무한)
/>

<Resource> 주요 속성 표

속성설명
nameDataSource에 대한 JNDI 이름 (DAO가 lookup할 때 쓰는 키)
auth인증 주체 (Container = 톰캣이 관리)
typeDB 종류별 DataSource 클래스
driverClassName연결할 DB 종류에 따른 드라이버 클래스 이름
url접속할 DB 주소와 포트 번호 및 SID
username / passwordDB 접속 ID / 비밀번호
maxActive동시에 최대로 DB에 연결할 수 있는 Connection 수
maxIdle동시에 idle(대기) 상태로 있을 수 있는 최대 수
maxWait새로운 연결이 생길 때까지 기다릴 수 있는 최대 시간

다른 속성들은 고정적으로 사용되며, 주로 driverClassName, username, password, url만 변경해서 사용합니다.

🧠 이해도 점검 퀴즈


  

    
Q1. 커넥션풀을 사용하는 가장 큰 이유는?

    
    
    
    
✅ 접속 "생성"이 느린 작업입니다. 미리 만들어 두고 빌려 쓰면 요청마다 생성 시간이 사라집니다. (생성은 한 번, 사용은 여러 번)

  


  

    
Q2. DAO 코드의 lookup("jdbc/oracle") 에서 "jdbc/oracle"은 무엇과 짝을 이루는가?

    
    
    
    
✅ context.xml에 등록한 name(key)과 DAO의 lookup(key)이 정확히 일치해야 톰캣의 JNDI 저장소에서 커넥션풀(value)을 꺼낼 수 있습니다.

  


  

    
Q3. 커넥션풀 환경에서 con.close()의 실제 동작은?

    
    
    
    
✅ 풀에서 빌린 연결의 close()는 "반납"입니다. 반납해야 다음 요청이 그 연결을 다시 빌릴 수 있습니다. 그래서 finally에서 반드시 호출합니다.
