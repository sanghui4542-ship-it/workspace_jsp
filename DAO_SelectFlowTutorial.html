Connection (T4CConnection)

오라클 서버와의 연결 통로. 접속 상태를 관리한다. 테이블이 아니라 서버 자체와 연결된다.

Statement

SQL 문장을 오라클로 전송해 실행을 요청하는 객체. 실행 자체는 오라클이 한다.

ResultSet

조회 결과를 한 행씩 읽어오는 커서. 결과 전체를 담는 게 아니라 읽는 통로다.

MemberVO

회원 1명(=1행)의 값 5개를 담는 상자. 행이 3개면 3개 만들어진다.

ArrayList

완성된 MemberVO들을 순서대로 담는 가변길이 배열. 최종적으로 서블릿에 반환된다.

🧠 이해도 점검 퀴즈

Q1. 장면 8에서 확인했듯, executeQuery() 직후 커서의 위치는?

✅ 커서는 첫 행 직전에서 시작합니다. 그래서 첫 행을 읽으려면 반드시 next()를 먼저 1번 호출해야 합니다.

Q2. 회원이 3명일 때 rs.next()가 호출되는 총 횟수와 마지막 반환값은?

✅ 1·2·3행에서 true 3번 + 행이 끝난 뒤 false 1번 = 총 4번. 장면 15에서 4번째 next()가 false를 돌려주며 while이 끝났습니다.

Q3. 장면 16의 ResourceClose()에서 닫는 올바른 순서는?

✅ rs는 stmt로, stmt는 con으로 만들어진 의존 관계이므로 안쪽 자원(rs)부터 닫습니다. close()는 메모리 삭제가 아니라 DB 자원 반납입니다.
핵심 정리 3줄
  1. 흐름은 드라이버 로딩 → Connection → Statement → executeQuery → ResultSet — SQL 실행은 자바가 아니라 오라클 서버가 한다.
  2. 커서는 첫 행 직전에서 시작하고, next()는 이동+true/false 반환을 동시에 한다 (3행이면 4번째 호출이 false).
  3. 행 1개 = MemberVO 1개로 포장되어 ArrayList에 담기고, finally에서 rs→stmt→con 순서로 자원을 반납한 뒤 배열이 서블릿으로 반환된다.
